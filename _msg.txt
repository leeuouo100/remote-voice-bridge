feat(v1.0.10): 一键修「换 USB 口就连不上」——含「删设备」卡死（ACL 接管）

诊断（只读，不需要管理员）
- pairing.py：把「配对记录 / 关联节点 / 活地址」摆在一起判定，6 种状态
  OK / STALE_ADDR / NODE_PHANTOM / RECORD_OK_NO_NODE / RECORD_NO_ADDRESS / NO_RECORD
- 终审是真的 from_id_async 打开一次：注册表一致 != 能用（真机上栽过）
- --acl-probe（提权、只探不删）· --acl-dump（提权、列所有者 + 每条 ACE）

修复（提权，动注册表前 reg export 备份，--restore-backup 可回滚）
- 默认阶梯 migrate -> rebuild：都不碰地址，**不需要重新配对**
- restore 降级：实测改不动 DeviceAddressCache（驱动会写回）
- rebuild 删节点让 Windows 按当前适配器重建；删之前先探能不能删干净（半删比不删更难收拾）

「删除失败」的根因与出路（武哥原话：「删除失败」）
- Enum\BTHLE\Dev_<远端>\<实例>\Properties 的 ACL 只放 SYSTEM：提权实测
  连 READ_CONTROL 都 rc=5，管理员 WRITE_OWNER 也拒 —— 设置里「删除设备」卡死同一个根
- 新增 --take-ownership：先拿所有权再改 DACL 再删。三个特权要一起开
  （SeTakeOwnership + SeRestore + SeBackup），只开第一个实测仍被拒；
  且要循环到不动点（第 1 轮解 Properties，第 2 轮才轮到拒绝继承的 {GUID} 子键）；
  拿不到「真能删」的确认就绝不动手。默认不开（会改系统键 ACL）
- 非管理员不下「删不动」的结论：不然报告会把权限问题说成 ACL 问题，
  等于把用户劝退到「没救」——结论错比不给结论更糟
